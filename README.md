# ticketflow - система бронирования мест на события

## Стек

Go, Gin, PostgreSQL, Redis, Docker Compose

## Требования

* Go 1.25.7
* Docker

## Запуск 

```bash
docker compose up -d
docker compose exec -T postgres psql -U ticketflow -d ticketflow < migrations/0001_init.sql
cp .env.example .env
go run ./cmd/seed
GIN_MODE=release go run ./cmd/api
```
`go run ./cmd/seed` печатает id события.

Go не читает `.env` сам. Чтобы подгрузить его, выполни перед запуском `set -a; source .env; set +a`.

Если миграция не применяется сразу после `docker compose up -d`, Postgres ещё стартует: подожди пару секунд и повтори.

Проверка 
```bash
curl http://localhost:8080/health
```
Ожидаемый ответ: `{"status":"ok"}`.

## Эндпоинты:
 1) `GET /events/:id/seats`: карта мест
 2) `POST /events/:id/reserve`: резерв любого свободного места
 3) `POST /events/:id/seats/:seat_id/reserve`: резерв конкретного места
 4) `POST /events/:id/seats/:seat_id/confirm`: подтверждение брони

Метод POST требует тело `{"user_id": "<uuid>"}`, авторизации пока нет, в реальной системе id берется из токена.

### Пример запроса
```bash
curl -X POST http://localhost:8080/events/<event_id>/reserve \
 -H "Content-Type: application/json" \
 -d '{"user_id":"<uuid>"}'
```

## Коды ответов
 1) 200: успех
 2) 400: невалидный id или тело запроса
 3) 403: бронь держит другой пользователь
 4) 404: место не найдено
 5) 409: места нет, место занято или бронь истекла

## Дизайн

 1) **Postgres**: источник истины, таблицы venues, events, seats хранение объектов, bookings история бронирований, event_seats основная таблица для бронирований.
 2) **Блокировки**: FOR UPDATE SKIP LOCKED при бронировании любого места, FOR UPDATE при бронировании конкретного места гарантируют, что место получит ровно один клиент.
 3) **Счётчик свободных мест в Redis**: эвристика, Postgres остаётся источником истины. Завышенный счётчик безопасен (лишний запрос проверит Postgres), заниженный опасен (отказ при наличии мест), поэтому есть компенсация при сбое и сверка раз в минуту.
 4) **Кэш карты мест**: живёт 30 секунд и сбрасывается при каждом изменении.
 5) **Фоновый воркер**: каждые 10 секунд освобождает просроченные брони.
 6) **Время**: всегда считается по часам базы, а не приложения.

## Тесты

**Нагрузочный тест**: 200 параллельных запросов на 15 мест дают ровно 15 броней; счётчик отсёк около 185 запросов от Postgres, запуск командой
```bash
go run ./cmd/loadtest
```

Перед запуском остановить API, иначе фоновые воркеры исказят подсчет транзакций.

**Интеграционный тест**: ходит в настоящие Postgres и Redis, перед тестированием запустить `docker compose up -d`, иначе тесты пропускаются. 
Запуск командой 
```bash
go test ./internal/service -race -count=1
```
